Payment flow

Pay by QR code and track order status

For this static website, QR payment is shown as a demo. For a real shop, every order should generate a unique order number and a unique QR payment reference. The payment gateway then sends your website a webhook when the payment is successful, so the order status changes automatically from "Pending Payment" to "Paid".

1. Customer places order 2. Website creates order ID 3. Customer pays unique QR 4. Gateway webhook marks order paid

How you know they ordered and paid

Recommended payment and order confirmation design

The safest design is to use a backend order system plus a payment gateway webhook. Do not rely only on screenshots, because screenshots can be late, duplicated, or fake.

01

Order created

Customer fills name, phone, delivery address, vehicle details, and selected parts. Website saves an order with status Pending Payment.

02

Unique QR generated

The payment gateway creates a QR code containing the exact amount and order ID, for example AP-2026-10025.

03

Payment verified

When payment succeeds, the gateway calls your webhook. Your database marks the order as Paid and records transaction ID, amount, and time.

04

Seller notified

You receive email, WhatsApp, or dashboard notification. Staff can pack the item, update to Processing, then add tracking.

What to build for real payment confirmation

  • Database: orders, order_items, payments, customers, shipments.
  • Payment gateway: DuitNow QR, Stripe, Billplz, ToyyibPay, iPay88, PayPal, or local bank/e-wallet provider.
  • Webhook endpoint: receives payment success/failure from the gateway and updates order status automatically.
  • Admin dashboard: shows Pending Payment, Paid, Processing, Shipped, Cancelled, and Refunded orders.
  • Notifications: send email/WhatsApp to you and the customer when order status changes.
